ShotFinder

Imagination-Driven Open-Domain Video Shot Retrieval via Web Search. ShotFinder starts from a remembered shot—not a known title or a closed candidate pool—and reconstructs the likely source-video context before searching the web and grounding the exact moment.

arXiv 2601.23232 Video imagination Search-engine retrieval Shot localization
My role

Second author with equal contribution. Tao Yu served as project leader. My work contributed to the open-domain retrieval formulation, system development, and empirical evaluation.

Benchmark

Search the open web from a shot description and practical constraints

1,210 Human-verified YouTube retrieval samples.
20 Topics covering diverse real-world video content.
6 Base and constraint-aware shot-retrieval tasks.

The six settings comprise a base shot-description task plus Temporal, Color, Visual Style, Audio, and Resolution constraints. These controls make the benchmark closer to how users refine an uncertain memory during real search.

Core insight

Imagine the missing video-level context before searching

A shot-level description often omits the title, creator, topic, and surrounding story that a search engine needs. ShotFinder uses a language model to imagine plausible source-video contexts, then turns those hypotheses into multiple web-search queries. Search is treated as abductive reconstruction rather than direct embedding lookup.

\[ \begin{aligned} \text{shot description} &\xrightarrow{\text{Video Imagination}} \{q_i\}_{i=1}^{M}\\ &\xrightarrow{\text{Web Search}} \{v_{ij}\}\\ &\xrightarrow{\text{MLLM localization}} (\hat v,\hat t). \end{aligned} \]
The output is both the retrieved source video \(\hat v\) and the localized target time \(\hat t\), not merely a ranked item in a predefined pool.
Stage 1

Generator

  • Interprets the remembered shot and any color, style, audio, resolution, or time constraint.
  • Imagines the broader source-video content that could contain the shot.
  • Produces diverse video-level search queries instead of one brittle literal query.
Stage 2

Retriever

  • Interacts with a web search engine rather than a closed benchmark index.
  • Filters and downloads the top candidate videos returned by generated queries.
  • Preserves query provenance so later verification can audit why a video was found.
Stage 3

Localizer: adapt visual and audio evidence to each candidate

Candidate duration and modality availability vary widely on the open web. The localizer therefore uses adaptive frame sampling, optional audio, and multimodal grounding to find a matching moment, followed by an explicit verification step.

Adaptive frame sampling Visual + optional audio evidence MLLM grounding Candidate verification
Research value

Why open-domain shot retrieval is different

No fixed pool

The target competes with the full web, so candidate acquisition is part of the task.

Two retrieval scales

The system must first find the source video and then localize the correct shot.

Auditable reasoning

Generated queries expose the hypotheses connecting a fuzzy memory to web results.
